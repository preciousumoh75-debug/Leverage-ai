# Issues

Use this folder for issue-style memory notes.

## When to create an issue note

- A task needs more than a few bullets.
- A decision depends on multiple steps.
- A request needs a clear owner, status, and follow-up.

## Suggested structure

- `open/`: active issue notes
- `resolved/`: completed or retired issue notes
- `history/`: archived copies of important resolved notes, if needed

## Archiving

- When an issue is complete, update its status, then move it to `resolved/`.
- If it is still useful as historical context, copy it to `history/` as well.
- Follow `.codex-memory/history/convention.md` for archive and changelog rules.

## Suggested fields

- Title
- Status
- Why it matters
- Next action
- Last updated
